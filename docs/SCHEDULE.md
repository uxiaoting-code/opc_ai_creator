## A. 2026-11-04 重排目标

本轮最高优先级调整为：**用户 App 的页面结构、视觉气质和交互链路尽量还原老师提供的 HTML/CSS/JS 原型。**

同时遵守三个边界：

1. 保留后端已经完成的 M0～M4，不为视觉改造重写订单、提交、审核、钱包和生成状态机。
2. 保留旧 Flutter 页面文件，通过新路由逐步替换主流程，不直接删除兼容入口。
3. 能真实接入的页面优先接真实接口；没有后端能力的页面才使用 Fixture / Mock，并且不能把 Mock 伪装成已完成的后端能力。

目标四 Tab：

```text
课程 | 创作 | 接单 | 我的
```

目标主流程：

```text
创作首页
→ 选择图片 / 视频 / 音频
→ 填写提示词并选择参数
→ 创建生成任务
→ 轮询任务状态
→ 查看生成结果
→ 提交到订单
→ 查看审核状态
→ 钱包入账 / 提现
```

接单链路：

```text
接单大厅
→ 订单详情
→ 立即接单
→ 带订单上下文去创作
→ 生成结果
→ 提交作品
```

| 角色 | 负责人 | 主要职责 | 文件范围 |

1. 保持 M0～M4 接口稳定。

4. 配合处理订单、任务、提交审核和钱包联调问题。

共享规则：

- 前端不直接修改 `docs/api-user.md`，发现字段问题先反馈给后端。

### C.6 每轮交接方式

每完成一个模块，按以下顺序交接：

1. 前端先完成页面和 Mock 数据，确认布局与交互。
2. 后端确认接口已完成并 push。
3. 前端 pull 后接真实接口。
4. 双方按该模块的 3～5 条验收用例走一遍。
5. 验收通过后提交代码，再进入下一模块。

推荐联调顺序：

```text
订单列表/详情
→ 接单和工作台上下文
→ 图片/视频/音频任务创建
→ 任务轮询和结果页
→ 提交和审核
→ 钱包、充值和提现
→ 作品列表
```
