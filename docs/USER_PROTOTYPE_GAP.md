# 用户端 Flutter 原型对照与开发顺序

> 参考原型：`docs/prototype-user/`（老师提供的 HTML/CSS/JS 移动端原型）。
> 对照代码：`lib/`（Flutter 用户 App）。
> 注意：这份原型不是 `admin-web/` 后台控制台，也不是要求直接嵌入 Flutter 的 WebView。
> 目标是把页面结构、视觉、交互和业务入口用 Flutter 重新实现，并保留调用后端 `/api/**` 的接口边界。

---

## 1. 原型的基本结构

原型是 390 × 844 的手机界面，底部只有 4 个一级 Tab：

```text
课程 | 创作 | 接单 | 我的
```

当前 Flutter App 的底部是 5 个 Tab：

```text
首页 | 任务 | 画廊 | 素材 | 我的
```

因此这不是“只补两个页面”的工作，而是一次**用户端信息架构调整**。现有页面可以复用组件和部分业务代码，但导航壳、首页结构和页面归属需要按原型重构。

原型的颜色令牌已经在 `lib/core/theme/app_colors.dart` 中落地：

- 暖白 `#F7F7F5`
- 蜜桃 `#FBE8DC`
- 奶油 `#F5EDDE`
- 鼠尾草绿 `#7C9A7E`
- 香槟金 `#C9A96E`
- 灰褐 `#8B8178`
- 柔炭黑 `#1C1C1E`

## 3. 开发顺序

### 第 1 阶段：组件和主题（先做，不接真实接口）

先建立用户端公共组件，数据通过参数传入，事件通过回调返回：

1. `PhonePageScaffold`：手机页面外壳、顶部状态栏、安全区、底部操作区
2. `GlassCard` / `PremiumPanel`：毛玻璃卡片、圆角、阴影
3. `PremiumTopBar`：标题、返回、右侧操作
4. `CreationModeSwitch`：图片 / 视频 / 音频模式切换
5. `UploadSlot`：参考图、商品图上传和预览
6. `ChipSelector`：风格、比例、数量、参数选项
7. `ParamSliderRow`：强度、创意度等参数
8. `ModelPickerSheet`：模型、供应商、算力消耗、推荐标识
9. `GenerateActionBar`：预计算力、余额、生成按钮、不可用状态
10. `TaskProgressBar`：进行中的任务、倒计时、继续创作
11. `ResultGallery`：多图、视频、音频结果和操作栏
12. `PremiumBottomSheet`：统一底部弹层
13. `EmptyState` / `LoadingState` / `ErrorState`

当前已有的 `lib/widgets/creation/` 和 `lib/widgets/premium/` 可以先复用，但必须按原型逐项核对，不要重新发明一套视觉语言。

### 第 2 阶段：重构导航壳和创作主流程

按原型实现 4 个一级 Tab：

```text
课程 / 创作 / 接单 / 我的
```

优先完成：

1. 创作首页
2. 图片生成
3. 视频生成
4. 生成结果
5. 音频生成
6. 场景列表
7. AI 抠图
8. 数字人播报

其中图片和视频先使用现有生成任务接口和 Mock Provider，音频、抠图、数字人先通过 repository 接口和 Mock 数据把 UI 闭环跑通。

### 第 3 阶段：课程和接单业务

1. 课程中心
2. 课程详情
3. 接单大厅
4. 接单任务详情
5. 提交状态
6. 接单记录

接单大厅和现有“我的生成任务”必须分开建模，不能直接复用同一张任务表而不改语义。

### 第 4 阶段：我的、钱包和成长体系

1. 我的
2. 我的荷包
3. 提现
4. 购买积分
5. 作品
6. 创作者等级
7. 经验规则
8. 我的徽章
9. 徽章详情
10. 培训报名
11. 报名成功
12. 我的报名
13. 报名详情
14. 考核结果

### 第 5 阶段：接后端和联调

每个页面只能通过 repository / API client 获取数据：

- 用户作品和生成任务：`/api/tasks/**`、`/api/works/**`
- 素材：`/api/materials/**`
- Prompt / Skill：`/api/prompts/**`、`/api/skills/**`
- 课程、接单、钱包、等级、培训：若后端没有对应接口，先补接口契约，再接真实数据

不能把 API Key、模型供应商凭证、Harness 节点配置写进 Flutter 客户端。

## 4. 必须一起确认的产品问题

在开始删除或重命名现有页面之前，需要和老师确认：

1. 原型中的 28 个页面是否都要作为答辩必做页面，还是只要求创作主流程和 4 个一级 Tab 必须复刻？
2. “接单大厅”是否是本次课程设计必须实现的业务，还是仅作为原型展示入口？
3. 课程、钱包、提现、积分、创作者等级、培训报名是否需要真实后端，还是允许 Mock 数据？
4. 现有 13 页需求清单与老师新原型的关系：旧功能保留为二级页面，还是以新原型替换旧信息架构？

在这些问题确认前，**不删除任何现有页面**，先做组件和页面结构对照。

---

## 5. 当前结论

- `docs/prototype-user/` 是用户端 Flutter 原型的唯一视觉基准。
- `admin-web/` 是后台控制台，不要再用它作为 Flutter 页面复刻目标。
- 现有 Flutter 13 页不能直接视为“已完成原型复刻”，至少需要重构主导航、创作首页、图片/视频流程，并补齐原型中的大量页面。
- 先做组件，再按 4 个一级 Tab 逐页实现；接口未完成时用 repository + Mock 保持 UI 可运行。
